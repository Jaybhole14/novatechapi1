# TaskFlow REST API Documentation

**Local base URL:** `http://localhost:3000`

All API responses use JSON. Browser-based documentation is also available at `/docs` while the server is running.

## Task model
```json
{
  "id": 1,
  "title": "Learn REST APIs",
  "description": "Practise CRUD operations",
  "completed": false,
  "created_at": "2026-10-14 12:00:00"
}
```
- `id`: database-generated integer.
- `title`: required string, 1–120 characters.
- `description`: optional string, up to 1000 characters.
- `completed`: boolean, defaults to false.
- `created_at`: timestamp generated by SQLite.

## Endpoints

### List tasks
`GET /api/tasks` — returns `{ "data": [], "count": 0 }` with `200 OK`.

### Get one task
`GET /api/tasks/:id` — `200 OK`; invalid ID returns `400`; missing task returns `404`.

### Create task
`POST /api/tasks` — send `Content-Type: application/json` and a body:
```json
{"title":"Study Java","description":"Practise for 30 minutes","completed":false}
```
Returns `201 Created`. Invalid fields return `400 Bad Request`.

### Replace task
`PUT /api/tasks/:id` — requires a valid `title`; `description` and `completed` can be supplied or default. Returns `200`, `400`, or `404`.

### Partially update task
`PATCH /api/tasks/:id` — send only fields to change, e.g. `{"completed":true}`. Returns `200`, `400`, or `404`.

### Delete task
`DELETE /api/tasks/:id` — returns `200 OK` with a confirmation message or `404` if missing.

## Error formats
Validation error:
```json
{"error":"Validation failed.","details":["title is required and must be a non-empty string."]}
```
Other errors include `{"error":"Task not found."}`, `{"error":"Route not found."}`, and `{"error":"Invalid JSON in request body."}`.

## Status codes
- `200 OK`: read/update/delete succeeded
- `201 Created`: creation succeeded
- `400 Bad Request`: invalid request
- `404 Not Found`: resource/route missing
- `500 Internal Server Error`: unexpected server error
